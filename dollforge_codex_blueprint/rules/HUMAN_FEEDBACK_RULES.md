# Human Feedback Rules

1. Toda edição deve gerar evento.
2. Guardar before/after quando possível.
3. Texto livre não substitui reason code.
4. Um reject deve apontar target e dimension.
5. Reprocessar apenas descendants inválidos.
6. Aprovação final não apaga warnings.
7. Feedback conflituoso deve ser preservado, não sobrescrito.
8. Revisor pode marcar `uncertain`.
9. Nota final deve ser multidimensional.
10. Apenas aprovação explícita promove para gold.
